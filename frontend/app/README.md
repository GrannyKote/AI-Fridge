# AI-Fridge (PWA)

Клиентская часть дипломного проекта: React + Vite с поддержкой установки как PWA.
Сейчас реализованы экраны авторизации и регистрации, данные приходят из API
бэкенда (`../../backend`).

## Запуск

Сначала нужно поднять бэкенд на `http://127.0.0.1:8000`, иначе формы будут
показывать «Сервер недоступен».

```bash
npm install
npm run dev      # http://localhost:5173
```

Запросы к `/api/*` Vite проксирует на бэкенд — и в `dev`, и в `preview`.
Адрес можно переопределить переменной `VITE_API_PROXY`, а если фронтенд
и API разнесены по разным доменам — задать полный адрес через `VITE_API_URL`.

Другие команды:

```bash
npm run build    # production-сборка в dist/ вместе с service worker
npm run preview  # локальный просмотр production-сборки
npm run lint     # проверка кода oxlint
npm run icons    # перегенерация иконок PWA из public/logo.svg
```

## Установка как приложение

Манифест и service worker генерируются плагином `vite-plugin-pwa`
(режим `autoUpdate`, офлайн-кэш через Workbox).

В разделе «Настройки → Режим работы» можно включить **Offline-first**.
Первую загрузку кладовой, покупок и справочников выполните при подключении.
Дальше изменения этих данных сохраняются на устройстве и отправляются по порядку
при восстановлении связи с открытым приложением. В настройках видны очередь
и ошибки синхронизации. При пустой очереди можно вернуться в **Online-only**,
который включён по умолчанию. Нужна миграция бэкенда `0019`.

### Сетевые профили для тестирования

Запустите фронтенд и API. Откройте Chrome или Edge с отдельным профилем браузера
и портом отладки. Например, для Edge в PowerShell:

```powershell
& "${env:ProgramFiles(x86)}\Microsoft\Edge\Application\msedge.exe" --remote-debugging-port=9222 "--user-data-dir=$env:TEMP\ai-fridge-network-test" http://127.0.0.1:5173
```

Оставьте в этом окне одну вкладку с AI-Fridge. Из каталога `frontend/app`
запустите профиль командой `npm run network:profile -- slow`, заменяя `slow`
именем нужного профиля.

| Профиль | Условия |
| --- | --- |
| `stable` | Без добавленной задержки и ограничения скорости |
| `slow` | Задержка 400 мс, загрузка 400 кбит/с, отправка 100 кбит/с |
| `intermittent` | 12 секунд связи, затем 8 секунд оффлайна, по кругу |
| `offline` | Сетевые запросы вкладки отключены, локальный кэш доступен |

Для переключения остановите текущий профиль через Ctrl+C и запустите новый.
Ctrl+C восстанавливает обычное подключение вкладки. Перед офлайн-проверкой
войдите в приложение и загрузите кладовую и покупки в режиме Offline-first.
Для проверки повторного открытия без сети используйте production-сборку
(`npm run build`, затем `npm run preview -- --port 4173`) и передайте её адрес
после имени профиля: `npm run network:profile -- offline http://127.0.0.1:4173`.

### E2E-тесты Playwright

Запустите локальный PostgreSQL и настройте `backend/.env`. У пользователя БД
должно быть разрешение на создание схем. Тесты сами запускают Vite и FastAPI
на портах 15173 и 18000, создают отдельную схему, применяют миграции и наполняют
её демоданными. По завершении схема удаляется. Каждый сценарий кладовой
готовит свой продукт и запускается независимо.

Из каталога `frontend/app`:

```powershell
npm ci
npx playwright install chromium
npm run test:e2e
```

По умолчанию используется Python из `backend/.venv`. Другой интерпретатор
можно указать через `PLAYWRIGHT_PYTHON`, другой браузер Chromium через
`PLAYWRIGHT_CHANNEL`, например `msedge`.

- Chrome / Edge на компьютере: иконка установки в адресной строке либо кнопка
  «Установить приложение» на экране входа.
- Android: меню браузера → «Установить приложение».
- iOS (Safari): «Поделиться» → «На экран "Домой"».

Для установки нужен `https` или `localhost`. Чтобы проверить на телефоне,
удобно поднять сборку через `npm run preview -- --host` и открыть адрес из
локальной сети по https-туннелю.

## Структура

```
src/
  api/           запросы к бэкенду
  auth/          контекст авторизации и сохранение сессии
  components/    переиспользуемые элементы форм и иконки
  lib/           валидация полей
  pages/         экраны: вход, регистрация, домашний
  styles/        стили экранов
```

## Экраны

- `/login` — вход: поля «Логин» и «Пароль», кнопка «Войти» и кнопка
  «Зарегистрироваться», открывающая экран регистрации.
- `/register` — регистрация: «Логин», «Пароль», «Повторить пароль» с проверкой
  совпадения паролей и занятости логина.
- `/` — «Кладовая», открывается после входа и доступна только авторизованному
  пользователю: сводка, поиск, фильтр по категориям и продукты, сгруппированные
  по сроку годности.

Продукты приходят из `user_group_product` для группы вошедшего пользователя,
категории — из `product_category`. Сроки считаются от поля `best_before`:
до конца срока меньше 0 дней — «Просрочено», до 4 дней — «Скоро испортится»,
дальше — «Свежие». Кнопки на карточке (использовать и удалить) убирают запись
из кладовой через API.

Нижняя панель с разделами «Кладовая», «Прогнозы», «Покупки» и «Профиль» скрыта
и открывается кнопкой-бутербродом в шапке; там же кнопка «Выйти».

## Про хранение данных

Пользователи хранятся в PostgreSQL и создаются бэкендом. Токенов пока нет:
после успешного входа профиль (`id`, `login`, группы) кладётся в `localStorage`
ключом `ai-fridge:session` и оттуда восстанавливается при перезагрузке
(`src/auth/sessionStore.js`).
