# AI-Fridge — бэкенд (FastAPI)

API авторизации для дипломного проекта. Работает с локальным PostgreSQL,
схема `diplom_all` базы `diplom`. Таблицы уже существуют, миграции не создаются:
приложение только читает и пишет данные.

## Запуск

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

Документация Swagger — http://127.0.0.1:8000/docs.

## Настройки

Параметры читаются из `.env` (шаблон — `.env.example`):

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `DATABASE_URL` | `postgresql+psycopg://postgres:postgres@127.0.0.1:5432/diplom` | Строка подключения |
| `DB_SCHEMA` | `diplom_all` | Схема с таблицами проекта |

## Эндпоинты

| Метод | Путь | Описание |
| --- | --- | --- |
| `POST` | `/api/auth/register` | Регистрация: создаёт пользователя и его группу |
| `POST` | `/api/auth/login` | Вход по логину и паролю |
| `GET` | `/api/health` | Проверка связи с базой |

Тело запроса для обоих методов авторизации:

```json
{ "login": "ivan.petrov", "password": "secret123" }
```

Ответ:

```json
{
  "id": 1,
  "login": "ivan.petrov",
  "groups": [{ "id": 1, "name": "Новая группа пользователей" }]
}
```

Коды ошибок: `409` — логин занят, `401` — неверный логин или пароль,
`422` — логин или пароль не прошли валидацию, `503` — нет связи с базой.

## Логика регистрации

Одной транзакцией (`app/services/users.py`):

1. в `diplom_all.user` добавляется пользователь;
2. в `diplom_all.user_group` создаётся группа «Новая группа пользователей»;
3. в `diplom_all.user_group_user` записывается связь пользователя с этой группой.

Если любой шаг падает, транзакция откатывается целиком.

## Структура

```
app/
  main.py            приложение FastAPI, CORS, /api/health
  config.py          настройки из .env
  database.py        engine, сессии SQLAlchemy
  models.py          модели user, user_group, user_group_user
  schemas.py         схемы запросов и ответов
  routers/auth.py    эндпоинты регистрации и входа
  services/users.py  работа с пользователями и группами
```

## Важно про пароли

По условию задачи пароли хранятся **в открытом виде** — так их кладёт
`services/users.py` и так же сравнивает при входе. Для реальной эксплуатации
это недопустимо: понадобится хеширование (например, bcrypt через `passlib`)
и выдача токена вместо возврата профиля.

Ещё одно место на будущее: в таблице `user` нет уникального индекса по `login`.
Занятость логина проверяется запросом перед вставкой, поэтому при
одновременных регистрациях теоретически возможны дубликаты. Надёжнее добавить
в базу уникальный индекс:

```sql
create unique index user_login_lower_key on diplom_all."user" (lower(login));
```
