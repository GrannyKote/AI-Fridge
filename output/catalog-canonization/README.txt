Проверка канонизации названий продуктов AI-Fridge

Результаты эксперимента находятся в results/report.txt. Исходные данные и
сохранённые предсказания позволяют пересчитать выводы. В этом комплекте
пересчитаны метрики по 7 668 сохранённым предсказаниям и сырым записям
27 прогонов Locust. Новый прогон PostgreSQL и Locust не выполнялся.

Повторный анализ без базы данных

    python -m pip install matplotlib pytest psycopg
    python -m pytest test_experiment.py -q
    python summarize.py
    python report.py

Команды выполняются из директории комплекта. summarize.py сверяет
предсказания с разметкой и пересчитывает метрики, процентили и карту полноты.

Стенд и воспроизведение

• Python 3.12, FastAPI, Uvicorn, psycopg, pytest, Locust и matplotlib.
  Измерения выполнены на PostgreSQL 17.7, pgvector 0.8.7, Locust 2.47.0,
  Windows и Intel Core i7-12700K, клиент, API и БД на одной машине.
• Создайте выделенную пустую PostgreSQL 17 БД catalog_bench_ru. Расширения
  pg_trgm и vector должны быть доступны для CREATE EXTENSION.
  На Windows использован TEMPLATE template0, LOCALE_PROVIDER icu,
  ICU_LOCALE 'ru-RU' и LC_CTYPE 'Russian_Russia.1251' при UTF8.
  Для других ОС нужна UTF-8-локаль с поддержкой кириллицы в pg_trgm.
  check_locale.py проверяет фактическое разбиение на кириллические триграммы.
• Из директории комплекта в PowerShell выполните команды ниже. Измерительный
  скрипт очищает только экспериментальную таблицу catalog_eval.product
  в выделенной БД. Укажите строку подключения в CATALOG_DSN.

    $env:CATALOG_DSN = 'postgresql://postgres@127.0.0.1:55439/catalog_bench_ru'
    python dataset.py
    python -m pytest test_experiment.py -q
    python bench.py 1000 --quality
    python run_load.py --trials 3 --seconds 8
    python summarize.py
    python report.py

001_catalog.sql и 002_vector.sql создают отдельную экспериментальную схему
и индексы. run_load.py запускает отдельный FastAPI на 127.0.0.1:58039.
Параметры запроса, индексные планы и сырые измерения лежат в репозитории.
Рабочие маршруты, миграции Alembic и данные приложения в прогоне не участвуют.

Разметка

• catalog.csv содержит канонический ID и название. В базовом наборе
  продукт задан типом и отличительным признаком. Бренд и фасовка из
  сценариев известного бренда считаются атрибутами покупки.
• queries.csv содержит класс шума, ввод, целевой ID, ID близкого
  отвлекающего продукта и ID отсутствующего в каталоге продукта.
• Seed 402193. Неразмеченных пользовательских строк в выборке нет.

Режимы

• Baseline. Регистр приводится к нижнему. Подсказки выбираются по
  префиксу LIKE с экранированием. Автопривязка по точному совпадению.
• Гибрид. Unicode и токены нормализуются, затем применяется словарь.
  Уникальный точный ключ используется для автопривязки. В отсутствие
  точной подсказки кандидаты GiST-триграмм и русского FTS объединяются
  через RRF с константой 60 и максимумом 64 кандидата из каждого списка.
• pgvector. Общая нормализация, затем 128-мерные хешированные символьные
  n-граммы, косинус и HNSW с m=16, ef_construction=64, ef_search=64.
  Для подтверждённого использования индекса в этом режиме отключён
  последовательный просмотр. Автопривязка по уникальному ключу или
  при косинусной близости ≥ 0,90 и отрыве от второй позиции ≥ 0,06.

В results/quality.json приведены числители и знаменатели. В таблице по
классам дубль делится на число вводов существующего продукта, в итоговом
DCR дубли делятся на размер полученного справочника. В ranking.csv также
публикуется доля дублей среди созданных записей. FMR считается среди
автопривязок. Если знаменатель равен нулю, значение оставлено пустым.
Перцентили рассчитаны методом ближайшего ранга.

Фасовка в исходной разметке является частью текстового шума. Удаление её
из поискового ключа повторяет поведение измеренного модуля для названий.
Рабочий каталог и его операции записи в эксперименте не задействованы.
